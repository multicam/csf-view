# Feature: Extract the view context into its own module

## Context

The application shares view state between the canvas shell and its controls. Consumers must receive that state through an explicit provider, while a misplaced consumer must fail with a clear diagnostic instead of crashing later on a null property access.

## Scenarios

### Scenario: A consumer receives the provided view state

- **Given** a view consumer is rendered beneath the application's view provider with a valid view state
- **When** the consumer requests the current view
- **Then** it receives that view state with its filename and actions available
- **Priority:** critical

### Scenario: A consumer outside the provider gets a useful error

- **Given** a view consumer is rendered without an enclosing view provider
- **When** the consumer requests the current view
- **Then** rendering throws an Error whose message names the missing view provider
- **Priority:** critical

### Scenario: A missing initial document remains a valid empty view

- **Given** the application's initial load has completed without a saved document
- **When** the application renders the view
- **Then** it renders the empty-view path without relying on an asserted non-null snapshot
- **Priority:** important

## Coverage Categories

- **Normal:** covered by “A consumer receives the provided view state.”
- **Boundary:** covered by “A missing initial document remains a valid empty view.”
- **Failure:** covered by “A consumer outside the provider gets a useful error.”
- **Interruption:** N/A — context lookup is synchronous and owns no interruptible operation.
- **Cleanup:** N/A — the extracted context and hook acquire no resources.
- **Dirty worktree:** preserve unrelated existing files and limit the story diff to the context extraction, necessary import updates, its focused scenario test, and PRD metadata.

## Out of Scope

- Changing view persistence, renaming, saving, screenshot capture, or server-sent-event behavior.
- Redesigning the view-state shape or the application UI.

## Acceptance Criteria

- [ ] The context module exposes the context value type, context, and consumer hook.
- [ ] The context's real default admits absence instead of hiding it with a non-null assertion.
- [ ] A consumer outside the provider receives the named missing-provider Error.
- [ ] The app root imports the context and no longer owns the context declarations.
- [ ] No non-null assertions remain under `src/`.
- [ ] Type checking succeeds.
- [ ] All critical scenarios pass without changing the existing default test count.
