# Feature: Repoint the components and prove the cycle is gone

## Context

The application entry point may load the root, but no module beneath the root may import it back and recreate a dependency cycle. This architectural boundary must be enforced by the repository's normal quality gate so future reverse imports are rejected automatically.

## Scenarios

### Scenario: A clean source graph passes architecture validation

- **Given** no source module except the browser entry point imports the application root
- **When** the architecture check runs
- **Then** it exits successfully
- **Priority:** critical

### Scenario: A reverse dependency fails architecture validation

- **Given** a source module other than the browser entry point imports the application root
- **When** the architecture check runs
- **Then** it exits non-zero and identifies the prohibited dependency
- **Priority:** critical

### Scenario: The repository gate enforces the architecture boundary

- **Given** the source graph is clean
- **When** the repository check runs
- **Then** architecture validation, linting, type checking, and the complete test suite all succeed
- **Priority:** critical

### Scenario: Existing behavior remains unchanged

- **Given** the two existing behavior test files are unmodified
- **When** the complete test suite runs after the dependency cleanup
- **Then** all 31 tests pass with zero failures
- **Priority:** critical

## Coverage Categories

- **Normal:** covered by “A clean source graph passes architecture validation.”
- **Boundary:** the browser entry point is explicitly allowed to import the application root while every other source module is rejected.
- **Failure:** covered by “A reverse dependency fails architecture validation,” including a recorded RED run before the temporary dependency is reverted.
- **Interruption:** N/A — dependency inspection and repository checks are finite commands with no resumable operation.
- **Cleanup:** N/A — the story acquires no resources and creates no persistent runtime state.
- **Dirty worktree:** revert only the temporary reverse import used for RED evidence, preserve unrelated work, and keep both existing behavior test files unmodified.

## Out of Scope

- Changing view-state behavior, persistence, saving, renaming, screenshots, or server-sent events.
- Redesigning the application UI or adding new runtime functionality.
- Reorganizing modules unrelated to the application-root import cycle.

## Acceptance Criteria

- [ ] A new architecture check (e.g. `scripts/check-architecture.ts`) exits non-zero when any module under `src/` other than `src/main.tsx` imports the application root, and exits 0 otherwise.
- [ ] Proven RED before GREEN: with a temporary reverse import present the check exits non-zero; record that evidence, then revert the import.
- [ ] `package.json`'s `check` script runs the architecture check alongside lint, types, tests.
- [ ] `bun run check` exits 0 on the clean tree.
- [ ] `bun test` reports 31 pass / 0 fail with `tests/persistence.test.ts` and `tests/server.test.ts` unmodified.
